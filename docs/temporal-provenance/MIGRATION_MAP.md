### Backfill decisions the implementation session must not guess

- A `valid_from default now()` value is not automatically a world-effective date. Establish a reliable source or import as observation-bounded/legacy-unknown. Preserve original value and migration origin in an immutable import artifact.
- Pair/kind relationship PKs may have overwritten earlier episodes. If retained receipts/captures cannot reconstruct them, report the gap rather than synthesizing a continuous lifetime.
- Fix missing tenant columns and add same-product/version/stream membership keys before new FKs. Existing single-column keys do not guarantee tenant or subject consistency.
- Do not drop global natural-key uniqueness until replacement identity/path-resolution constraints and consumers are ready. Host IDs and registry namespace policies require a verified mapping.
- Current cascade deletes must not remove retained evidence/temporal history. Replace with restricted deletion or governed tombstones; tenant erasure requirements need an explicit retention procedure and unavailable-content markers.
- A current lifecycle value cannot establish historical retraction/admission dates. Backfill it as an imported disposition at the new K unless historical receipts support more.
- Keep imports out of old knowledge snapshots: backfilled world history becomes known at a new admission K. Preserve any reconstructed historical knowledge coordinate separately with explicit confidence and origin.

### Schema dependency placement decisions

Store benchmark executions/results and case-study outcome→metric memberships in `ranking` or another permitted integration owner, pointing to corpus identities. Do not put a corpus FK into `ranking.metric_observation`, which reverses the existing DAG. Likewise use `research` to link research reports to corpus/content, and `retrieval` to link chunks to evidence supports. Foundational temporal metadata references only lower-level identity/receipt/artifact facilities; evidence points to temporal subjects. See the main handoff for the seal integration routine.

Before deployment: apply fresh chain AND upgrade a populated disposable copy; regenerate canonical types using the repository's prescribed command; commit migrations and types together; run server-role and application-role RLS checks. Do not use application-local migration trees. Keep all production target schema names and constraints in reviewed migrations rather than copying the isolated `industry_demo` schema into production.
