# Root review: semantic persistence candidate

The executable candidate is **not approved for promotion**. Its rollback-only compilation proves that PostgreSQL accepts the DDL; it does not prove its triggers execute correctly or preserve the existing extraction boundary. The original candidate remains outside canonical migrations.

1. The observation guard calls the shared scope predicate that also accepts extraction. It never independently requires the claims/report semantic tuple. A semantic observation must reject an extraction attempt, even when its lease and artifacts are otherwise valid.
2. Provider binding comparisons use nullable `<>` expressions in a PL/pgSQL `IF`. A null operation/profile/dispatch/request field can produce unknown rather than true, bypassing the intended rejection. Use null-safe exact comparisons and explicitly require every mandatory field.
3. The model truth-table CHECK admits SQL unknown: `model_status='matched'` with a null observed model can satisfy the CHECK without being true. Require explicit non-null equality for matched observations and test every null case.
4. The response envelope is selected by matching parents with `LIMIT 1`; its exact artifact ID, digest, type, provider-attempt binding and transformation signature are not required. Bind the canonical response-capture envelope directly, with no ambiguous lookup. The request-to-blinded-input parent closure is also missing.
5. The new security-definer scope function revokes PUBLIC execution without granting the intended trigger callers execution. Its use from invoker trigger functions therefore needs actual role-execution tests. Preserve all existing extraction update/reconciliation invariants when replacing the prior trigger function; compilation alone cannot establish parity.
6. The SQL observation omits producer-attempt identity, exact response-envelope identity and several fields of the newly implemented observation body. Usage limits differ from the strict contract, and timestamps/signature/body-field consistency are not validated. Complete the row/body mapping before adding a native adapter.

Required next evidence: a corrected exact row/contract mapping; rollback fixtures exercising the trigger as its real writer role; hostile null, family, fence, envelope and request-parent cases; unchanged extraction reservation/dispatch/reconciliation behavior; and an independent review. No semantic runtime or provider behavior is established by this candidate.
